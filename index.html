Computer Organization & Architecture: Unit 4 Fundamentals

A comprehensive masterclass on Single-Bus CPU Organization, Register Transfers, Micro-operations, and Control Unit Architectures.

🚌

1. Single-Bus Datapath Organization

In a single-bus datapath, all internal registers (PC, IR, General Purpose Registers R0–R7, MAR, MDR, Temp Y, and Temp Z) connect to a single common data bus.

Key Characteristic: At any given clock cycle, only one register can drive data onto the bus (place output using its tristate buffer `Rout`), while one or more registers can latch data from the bus (`Rin`).

This hardware simplicity reduces chip pin-count and routing complexity, but introduces sequential bottlenecks since simultaneous transfers cannot occur.

🔄

2. Register Transfers & Control Gating

Each register is accompanied by control lines:

  • R_in (Input Enable): When asserted high at clock edge, the register loads whatever binary word is currently on the common bus.
  • R_out (Output Enable): When asserted high, tri-state buffers connect the register's outputs to the bus. Otherwise, the register remains in a high-impedance state (Hi-Z).

Example: Moving data from R1 to R2 requires R1out, R2in asserted simultaneously within clock pulse T.

🧮

3. ALU Operations & Temp Registers Y and Z

The Arithmetic Logic Unit (ALU) is purely combinational logic requiring two stable inputs simultaneously to generate an output.

The Single-Bus Dilemma: How can two operands reach the ALU if only one value can exist on the bus at a time?

The Solution:
1. First operand is placed on the bus and latched into Register Y (R1out, Yin).
2. Second operand is placed on the bus (R2out).
3. ALU computes Add or Sub between Bus and Y.
4. Result cannot go straight to destination register because the bus is already occupied by R2! Hence, the result is captured in Register Z (Zin).
5. In the subsequent cycle, Z drives the bus into destination (Zout, R3in).
🔁

4. The Instruction Execution Cycle

Every machine instruction passes through three sequential phases:

  1. FETCH: PC contents copy to MAR (PCout, MARin). Read signal is issued. PC is incremented by 4 via ALU (Select4, Add, Zin -> Zout, PCin). Data returns from memory into MDR and transfers to IR (MDRout, IRin).
  2. DECODE: The Control Unit inspects the opcode in IR, determines the addressing modes, and activates the corresponding micro-step sequencer.
  3. EXECUTE: Micro-operations specific to the instruction run (e.g., ALU operations, address calculations, memory write, or conditional branch updates).
💾

5. Memory Interfacing: MAR, MDR, and WMFC

CPU clock speeds are dramatically faster than external DRAM access latency.

  • MAR (Memory Address Register): Unidirectional latch driving external address pins.
  • MDR (Memory Data Register): Bidirectional register with two sets of gating: MDRin/MDRout (internal bus) and MDRinE/MDRoutE (external memory data bus).
  • WMFC (Wait for Memory Function Completed): Causes CPU control sequence to stall until memory asserts the MFC acknowledge line, preventing race conditions.
⚙️

6. Control Unit Architectures Compared

Feature Hardwired Control Unit Microprogrammed Control Unit
Implementation Fixed combinational logic gates, decoders, and flip-flop counters. Control Store ROM holding micro-routines of control words.
Speed Extremely fast (direct gate propagation delay). Slower (requires control memory read cycle).
Flexibility Rigid; modifying instructions requires redesigning hardware. Highly flexible; instructions can be updated by rewriting ROM.
Chip Area & Cost Grows exponentially with instruction complexity (RISC). Systematic and cost-effective for large CISC instruction sets.
